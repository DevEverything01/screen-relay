# Real application qualification

Run sequentially from the workspace root, under the parent Docker scheduler:

```sh
rtk node native-stream-lab/experiments/engine-evaluation/qualification/applications.mjs --self-check
rtk proxy env APP_DOCUMENTS=/absolute/frozen-documents node native-stream-lab/experiments/engine-evaluation/qualification/applications.mjs native
rtk proxy env APP_DOCUMENTS=/absolute/frozen-documents node native-stream-lab/experiments/engine-evaluation/qualification/applications.mjs selkies
rtk proxy env APP_DOCUMENTS=/absolute/frozen-documents node native-stream-lab/experiments/engine-evaluation/qualification/applications.mjs kasm
```

APP_DOCUMENTS is required and must contain real, frozen `doc`, `icons` and `fonts` directories, with enough doc entries to scroll. Each fresh container receives the same tree at `/opt/qualification-documents`. The runner records a SHA-256 manifest before copying and asserts the destination manifest matches, including empty directories. Broken links, absolute symlinks and relative symlinks resolving outside the frozen tree are rejected; prepare a dereferenced tree if needed. The parent prepares this dataset once from real installed documentation/icons/fonts; no animated fixture is generated. No builds are needed. Native uses `native-stream-lab:general3`; competitors use immutable common-base image `sha256:aa2b9fe4228860fcae86829b1c609139f956f934236bbebdd50bcf143d356712`. Fresh containers share 2 CPUs, 1536 MiB memory without extra swap, 512 MiB shared memory, 1280×720 X11 and headless Chrome. Port 18100 must be free. Existing BENCH_PASSWORD comes from desktop-stream-bench/.env. Kasm retains the original comparison settings (video quality 10, 60 image/streaming frame rate); unrelated quality fields must remain unchanged. No engine source changes or custom application fixtures are introduced.

The workload opens real Thunar, uses browser Ctrl+L typing and Enter to navigate copied real doc, icons and fonts directories, then uses browser wheel events to scroll actual documentation entries. A bounded 10-second visible-window poll waits for Thunar readiness. Independent X11 window titles and focus confirm navigation. Source X11 captures and decoded captures document visible content before/after scrolling. Each run saves package versions and sorted actual directory inventories, so differences between image contents remain visible rather than being treated as streaming errors.

Raw browser rAF pixel hashes at 160×90, cgroup CPU/working-set memory/network endpoint counters, image identity, runner hash, screenshots, browser/decoder errors and logs are saved under qualification/results/applications-ENGINE-TIMESTAMP. The runner stops and preserves only its own container.

Visible change frequency is not FPS: compression noise, caret blink and UI feedback may contribute. The measured phase covers only 90 browser wheel steps at 250 ms intervals (about 22.5 seconds plus input dispatch), alternating down/up every ten steps and ending down. Navigation, native title/focus validation, settling, screenshot/scrot/copy and fidelity scoring occur outside its counters and rAF interval. Only browser rAF sampling and the cgroup endpoint probes remain measurement instrumentation. Settled RGB MAE/PSNR compare each engine's decoded desktop to its own real X11 desktop, including decorations; they are not cross-image content equality or motion fidelity scores. No synthetic expected image is used. Source and decoded capture are sequential, so caret/cursor timing can affect small regions. Producer rate and input latency remain unmeasured. Application/package differences can change rendering and workload cost; compare package versions before interpreting results. Folder contents themselves are verified identical to the frozen dataset. One local file-manager workload does not establish general application superiority.

Offline self-check protects RGB scoring against a known 10-level error and resource arithmetic against known byte counters/reversed time. Live checks additionally require real directory titles/focus, nonblack pixels, actual scroll changes and zero observed decoder errors. Browser errors are retained for triage.

Summary fields are also emitted at `phases.desktop`: CPU, memory, bandwidth, usefulVisualChangesPerSecond and frozenQuality. The latter is the final settled scroll-after MAE/PSNR; other samples are retained under qualitySamples; it is not a frame-rate measure.

The file-list correspondence gate uses the fixed desktop ROI x=250, y=180, width=900, height=400, excluding the title bar, location-field caret and surrounding desktop. Thresholds were declared before live execution: decoded-to-current-native RGB MAE must be at most 25. When native ROI change reaches MAE 0.1, decoded ROI must be at least 5% closer to current native content than to the previous native content (and strictly closer). The final native scroll viewport must change by MAE at least 0.1. Thus desktop blink alone cannot certify scrolling, and stale decoded content cannot certify a changed native view. Every evidence object retains full-frame quality and ROI correspondence scores even if the subsequent gate rejects it. These conservative operational gates are not perceptual-quality claims; dense nearly identical folder views may be inconclusive and must fail rather than be silently accepted. No thresholds are tuned per engine.

Offline negative controls now reject a stale decoded view and unrelated content, while accepting exact changed content and an unchanged matching view. Live browser/Docker validation remains the parent scheduler's responsibility.
