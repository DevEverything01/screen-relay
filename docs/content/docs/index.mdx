Relay streams a Linux desktop to your browser. You open a link to see the screen and use it with your mouse and keyboard. A program, such as an AI agent, can take screenshots and send clicks, keys, and text to the same desktop from the `relay` command line, a Node SDK, or an HTTP and WebSocket API.

Relay is for two groups of people:

- Operators who run a desktop on a Linux VM, sandbox, or container and want to watch or use it from a browser.
- Agent builders who need a program to see and control a real desktop with graphical apps.

## How it fits together

Relay has two sides:

- The **VM** is the Linux machine that shows the desktop. `relay up` starts a virtual display, a desktop, and the relay engine there. The engine captures the screen, streams it, and accepts input. Relay says "VM" for a container or sandbox too.
- The **client** is anything that talks to the engine: the browser viewer, or the `relay` CLI on the VM or on another machine, such as your laptop.

A running desktop is a **session**. Its name defaults to `default`.

## What you can do

- Watch and use the desktop in a browser. The viewer opens from a link that `relay up` prints.
- Take a screenshot and send clicks, key presses, and text from the CLI.
- Start graphical apps on the desktop with `relay run`.
- Control a session on a remote VM from your laptop with a URL and a token. See [Remote access](/docs/remote-access).
- Run the desktop in a container. See [Docker](/docs/docker).
- Give an agent step-by-step instructions with `relay skills get core`. See [Agent skills](/docs/agent-skills).

```sh
relay up -d
relay screenshot screen.png
relay click 0.5 0.5
relay type "hello"
relay key ctrl+l
relay down
```

Coordinates run from 0 to 1, measured from the top-left of the screen.

## Limits

| Area | Limit |
| --- | --- |
| Display server | X11 only. Wayland is planned. |
| Resolution | Up to 1920x1080, set in the config ([Configuration](/docs/configuration)). No live resize. |
| Control | One input owner at a time: a browser viewer or one agent. Screenshots work at any time. |
| Not supported | Audio, clipboard, IME, relative pointer, hardware encoding. |
| Auth | One shared token per session. No multi-user identity. |
| Install | The engine installs on Linux only, and automatic dependencies need apt (Debian or Ubuntu). `--client-only` installs the CLI on any OS with Node 26 or newer. |
| Browser | The viewer needs H.264 WebCodecs: current Chrome, Edge, or Safari. |

## Status

<Callout title="Experimental">
  Relay was tested on a fresh Vercel Sandbox (Ubuntu 26.04 x86_64): install,
  `up -d --public`, the viewer link, remote screenshot, click, type, and key, a
  busy response while a viewer is open, and a clean `down`. It was also tested
  in Docker (Debian trixie arm64), as a non-root user and as root. It was not
  tested on other distributions, over wide-area links, or in long runs.
</Callout>
