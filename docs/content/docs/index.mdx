Relay streams a Linux desktop to your browser. Open the link it prints to see the screen and use it with your mouse and keyboard. An agent can also control the same desktop from the `relay` command line, a Node SDK, or an HTTP and WebSocket API, taking screenshots and sending clicks, keys, and text. Relay runs the desktop on a Linux VM, container, or sandbox.

## Quickstart

On a Linux VM with Git and root or passwordless `sudo`, from a clone of the repository:

```sh
./install.sh
export PATH="$HOME/.local/bin:$PATH"
relay up
```

`relay up` starts the display, the desktop, and the engine, then prints a viewer link. Open it in a browser with H.264 WebCodecs, such as current Chrome, Edge, or Safari. Without `-d`, `up` stays in the foreground and Ctrl+C stops the session.

## How it works

<Diagram name="architecture" title="How relay connects the desktop, browser, and agent" aspectRatio="720 / 288" />

The same flow in text:

```text
Linux VM: Desktop (X11 or Wayland) -> relay engine (screen)
relay engine -> Browser (video)
Browser -> relay engine (clicks and keys)
Your agent (CLI, SDK, or HTTP) <-> relay engine (screenshots and input)
```

The VM runs a display and a desktop. The engine on the VM captures the screen, encodes it as H.264 video, and streams it to the viewer in the browser. The viewer, or an agent over HTTP or WebSocket, sends input back, and the engine applies it as keyboard and mouse input. Only one client can send input at a time. The stream lowers its bitrate on a slow link.

## Limits

| Area | Limit |
| --- | --- |
| Display server | X11 or Wayland on Linux; the Windows engine captures the signed-in desktop. `relay up` uses X11 when the engine includes it, otherwise Wayland. See [Wayland](/docs/wayland) for compositor requirements. |
| Resolution | Up to 16384x16384, set in [Configuration](/docs/configuration). A change applies when the session starts. |
| Control | One input owner at a time: a viewer or one agent. Screenshots work at any time. |
| Not supported | Audio, clipboard, IME, relative pointer, and hardware encoding. |
| Auth | One shared token per session; a session on loopback has none. No separate user identities. |
| Install | `install.sh` and `relay up` need Linux. On Windows you build and start the engine by hand; see [Windows](/docs/windows). Automatic dependencies cover Debian, Ubuntu, Fedora, Arch Linux, and Alpine. `--client-only` installs the CLI on any OS with Node 26 or newer. |
| Failure | Three capture failures in a row end the session. `relay logs` shows why. |
