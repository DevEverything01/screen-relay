screen-relay streams a Linux or macOS desktop to your browser. Open the link it prints to see the screen and use it with your mouse and keyboard. An agent can also control the same desktop from the `screen-relay` command line, a Node SDK, or an HTTP and WebSocket API, taking screenshots and sending clicks, keys, and text. screen-relay runs the desktop on a Linux VM, container, or sandbox, or attaches to a Mac's display.

## Quickstart

On a Linux VM with root or `sudo`, or on a Mac, with Node 22 or newer:

```sh
npm install -g screen-relay
screen-relay up
```

On a terminal, the first `screen-relay up` sets up the machine before it starts the session. Then `up` starts the display, the desktop, and the engine, and prints a viewer link. Open it in a browser with H.264 WebCodecs, such as current Chrome, Edge, or Safari. Without `-d`, `up` stays in the foreground and Ctrl+C stops the session.

## How it works

<Diagram name="architecture" title="How screen-relay connects the desktop, browser, and agent" aspectRatio="720 / 288" />

The same flow in text:

```text
Linux VM: Desktop (X11 or Wayland) -> screen-relay engine (screen)
screen-relay engine -> Browser (video)
Browser -> screen-relay engine (clicks and keys)
Your agent (CLI, SDK, or HTTP) <-> screen-relay engine (screenshots and input)
```

The VM runs a display and a desktop. The engine on the VM captures the screen, encodes it as H.264 video, and streams it to the viewer in the browser. The viewer, or an agent over HTTP or WebSocket, sends input back, and the engine applies it as keyboard and mouse input. Only one client can send input at a time. The stream lowers its bitrate on a slow link; see [How streaming works](/docs/how-streaming-works).

## Limits

| Area | Limit |
| --- | --- |
| Display server | X11 or Wayland on Linux, the logged-in user's display on macOS, or the signed-in desktop on Windows. On Linux, `screen-relay up` uses X11 when the engine includes it, otherwise Wayland. See [Wayland](/docs/wayland) for compositor requirements, [macOS](/docs/macos) for permissions, and [Windows](/docs/windows) for the Windows engine. |
| Resolution | Up to 16384x16384, set in [Configuration](/docs/configuration). A change applies when the session starts. |
| Control | One input owner at a time: a viewer or one agent. Screenshots work at any time. |
| Not supported | Audio, clipboard, IME, relative pointer, and hardware encoding. |
| Auth | One shared token per session; a session on loopback has none. No separate user identities. |
| Install | Run `npm install -g screen-relay` with Node 22 or newer. The first `screen-relay up` sets up the machine and builds the engine. Automatic package setup covers Debian, Ubuntu, Fedora, Arch Linux, and Alpine on Linux, and Homebrew on macOS 13.5 or later. On Windows, build and start the engine by hand; see [Windows](/docs/windows). |
| Failure | Three capture failures in a row end the session. `screen-relay logs` shows why. |
