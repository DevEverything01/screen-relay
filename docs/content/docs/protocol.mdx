Call screen-relay over HTTP from any language, or use the [CLI](/docs/cli) or [Node SDK](/docs/sdk) for most tasks.

## Read the screen

Start a session, then run these commands on the VM or through an [SSH tunnel](/docs/remote-access#ssh-tunnel):

```sh
curl -fsS http://127.0.0.1:8080/capabilities
curl -fsS http://127.0.0.1:8080/screenshot.png -o screen.png
```

These commands use the default address and a session bound to `127.0.0.1` without `--public`, which has no token. The screenshot is saved as `screen.png`.

For a session with a token, run `screen-relay status --json` on the VM to find its `tokenFile` path; add `--name NAME` for a named session. Replace `/path/to/token` with that path and add `-H "Authorization: Bearer $(cat /path/to/token)"` to each request. Use the HTTPS origin if the session uses TLS.

## Send input

<span id="text-events" />
<span id="input-events" />
<span id="input-records" />

Use the [CLI](/docs/cli) from any machine with `--url` and `--token-file`, or use the [Node SDK](/docs/sdk). Close the viewer or control session first; either blocks HTTP input.

```sh
screen-relay click 0.5 0.5 --url https://desktop.example.com --token-file ./token
```

Replace the URL and securely copy the session token into `./token`. For a local session, omit `--url` and `--token-file`. Text input uses the desktop's keyboard layout and can type characters absent from it.

`POST /input` takes binary records; see the [wire protocol](https://github.com/vercel-labs/screen-relay/blob/main/PROTOCOL.md) to write your own client.

## Endpoints

| Method | Path | What it does |
| --- | --- | --- |
| `GET` | <span id="get-capabilities" />`/capabilities` | Returns the desktop size, backend, features, and input limits as JSON. |
| `GET` | `/screenshot.png` | Returns a PNG without the cursor, even when another client owns input; maximum 8 MiB and a 5-second timeout. |
| `POST` | <span id="post-input" />`/input` | Sends a batch of binary input records. |
| `GET` | <span id="get-metrics" />`/metrics` | Returns stream and resource metrics as JSON. |
| `GET` | `/`, `/index.html`, `/viewer.js` | Serves the viewer. |
| WebSocket | `/stream` | Streams video, sends cursor images when supported, and accepts viewer input. |
| WebSocket | `/control` | Sends input and receives a response for each event, without video. |

## Authentication

When the session has a token, send `Authorization: Bearer TOKEN`. Do not put the token in a request URL. See [Tokens](/docs/remote-access#tokens).

The `Host` must be `localhost`, `127.0.0.1`, or the authority configured with `--public`, with its port if specified. `Origin` is optional. When the session has a token, any `Origin` is accepted. Without a token, a sent `Origin` must be a loopback origin with a loopback `Host`.

## Errors

<span id="limits" />

| Status | What to do |
| --- | --- |
| 400 `invalid_input` | Send a nonempty batch of valid records with the correct `Content-Length`. |
| 401 `unauthorized` | Send the correct session token. |
| 403 `forbidden` | Check the `Host` and `Origin` rules. |
| 404 `not_found` | Check the endpoint path. |
| 405 `method_not_allowed` | Use the method listed for the endpoint. |
| 409 `busy` | Close the input owner or wait, then check for partial input before retrying. |
| 411 `length_required` | Include `Content-Length` on `POST /input`. |
| 413 `too_large` | Send no more than 256 input records per request. |
| 422 `unsupported_input` | Change the input or keyboard layout. |
| 503 `busy` | Wait for the other screenshot to finish. |
| 503 `screenshot_unavailable` | Check `screen-relay logs engine` and try again. |

Errors are JSON with an `error` field. Input errors can include the failed record's zero-based `index` or an `applied` count. Do not use `applied` as a retry offset; check the desktop before retrying a partial batch.
