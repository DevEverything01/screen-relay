Use Node 26 or newer to send input and take screenshots. Start a desktop on the same machine with [relay up -d](/docs/getting-started#2-start-a-session).

## Install and import

Clone the [relay repository](/docs/getting-started#1-install-relay), then build and install it in your Node project:

```sh
(cd /absolute/path/to/this/repo && npm install && npm run build)
npm install /absolute/path/to/this/repo
```

### One-shot calls

Close the viewer, then click and save a screenshot:

```js
import { createClient } from 'relay';
import { writeFile } from 'node:fs/promises';
const desktop = createClient();
await desktop.click(0.5, 0.5);
await writeFile('screen.png', await desktop.screenshot());
```

## Two ways to connect

Use `createClient(options)` for one-shot actions such as `click` and `type`. Use `await connect(options)` to hold a WebSocket control session and send individual input events until `close()`.

### A control session

Close the session to release input:

```js
import { connect } from 'relay';

const desktop = await connect();
try {
  await desktop.input({ type: 'pointerMove', x: 0.5, y: 0.5 });
} finally {
  desktop.close();
}
```

The session exposes `surface: { width, height }` and allows 32 pending input requests. An acknowledgement timeout closes the session. Input is not replayed after disconnecting, and an acknowledgement does not guarantee the application reacted.

## One input owner at a time

A viewer, control session, or CLI can own input. Close the viewer or session before sending client input, or it returns `busy`. A control connection can return `unreachable` when input is held. Status, capabilities, and screenshots do not require input control.

## Methods

Coordinates are fractions from `0` to `1`, measured from the top-left. Client input methods return `{ events: number }`.

| Method | Result or action |
| --- | --- |
| `click(x, y, { button }?)` | Click with `left` (default), `middle`, or `right`. |
| `move(x, y)` | Move the pointer. |
| `scroll(x, y, { dx, dy }?)` | Scroll by integer notches after moving. Positive `dx` is right, positive `dy` is down; at least one must be nonzero. |
| `key(...combos)` | Press physical keys, such as `ctrl+l`; `cmd` and `meta` alias `super`. |
| `type(text)` | Send one event per Unicode scalar using the remote keyboard layout. Empty text sends nothing. |
| `input(events)` | Send a nonempty array of [input events](#input-events). |
| `capabilities()` | Backend, screen size, `fps`, `max_input_batch`, and features. |
| `status()` | Transport metrics; unavailable resource counters are `null`. |
| `screenshot()` | PNG bytes, without the viewer's cursor overlay. |

`capabilities(options)`, `status(options)`, and `screenshot(options, path?)` are also standalone exports. The latter returns PNG bytes and writes them to `path` if provided.

Input batches contain at most `max_input_batch` events, up to 256. A key combination or scroll must fit in one batch. Held keys and buttons are released at each boundary. Batches run in order and are not retried; await each call to keep actions in order.

### Session methods

| Method | Result or action |
| --- | --- |
| `input(event)` | Send one [input event](#input-events) and wait for acknowledgement. Returns no value. |
| `screenshot(path?)` | PNG bytes; writes them to `path` if provided. |
| `capabilities()`, `status()` | Same as the client methods. |
| `close()` | Close the session and release held keys and buttons. |

## Input events

| Type | Fields |
| --- | --- |
| `keyDown`, `keyUp` | `key`: USB HID usage from 0 to 231. |
| `pointerMove` | `x`, `y`: coordinates from 0 to 1. |
| `buttonDown`, `buttonUp` | `button`: 1 for left, 2 for middle, 3 for right; `x`, `y`. |
| `wheel` | `axis`: `vertical` or `horizontal`; `delta`: a multiple of 120 from -1200 to 1200; `x`, `y`. |
| `releaseAll` | No fields. |
| `text` | `codepoint`: Unicode scalar from 1 to 0x10FFFF, excluding surrogates. |

Optional `buttons` (0 to 31) and `modifiers` (0 to 255) default to 0. Both must be 0 for `text` and `releaseAll`.

## Options

Pass these options to `createClient`, standalone functions, or `connect`. Control sessions reject nonempty `ca` or `connect` with `invalid_option`.

| Option | Meaning |
| --- | --- |
| `url` | Origin only; default `http://127.0.0.1:8080`. HTTP only for `localhost` and `127.0.0.1`; HTTPS elsewhere. No credentials, path, query, or fragment. |
| `token` | 64 lowercase hexadecimal characters. Required for remote hosts. See [Tokens](/docs/remote-access#tokens). |
| `timeout` | Integer from 1 to 2147483647 milliseconds; default 10000. Per HTTP request, control connection, and input acknowledgement. |
| `ca` | Certificate file for HTTPS. Verifies the certificate but skips the hostname check. |
| `connect` | Address to dial instead of the URL host; the URL host remains the `Host` header. |
| `signal` | `AbortSignal` that cancels requests or the control session. |

Redirects are not followed. The engine closes screenshot requests after 5 seconds; screenshots larger than 8 MiB are rejected.

## Errors

Match `RelayError.reason`, not the message. `createClient` can throw during option validation; async calls reject. Errors also expose `code`, `message`, `class`, `exitCode`, `status`, and optional `hint`, `data`, and `next`. See [error reasons](/docs/cli#error-reasons).

| Reason | Cause and action |
| --- | --- |
| `busy` | Another input owner, a full input queue, 32 pending session requests, or another screenshot. Wait for it to finish before retrying. |
| `unauthorized`, `forbidden` | The engine rejected the token, host, or origin. Check the connection settings. |
| `unreachable`, `timeout` | Check the URL, network, and TLS certificate. Increase `timeout` if needed. |
| `disconnected` | The control session closed or was lost. Connect again. |
| `invalid_input`, `invalid_option` | Check the URL, token, input, and options. |
| `unsupported_input` | The backend cannot apply the event or type the character. Change the input or keyboard layout. |
| `component_failed` | The engine could not complete the request. For screenshots, check `relay logs engine` and [Wayland requirements](/docs/wayland#compositors). |
| `canceled` | The `signal` aborted the request or session. Use a fresh signal to retry. |
| `protocol_error`, `io_error` | The response was invalid or too large, or a local certificate or screenshot file could not be read or written. |

When an input request fails, `error.data?.applied` counts confirmed events. Some validation and protocol errors do not include it. If a reply was lost or invalid, the last batch may also have been applied: check a screenshot before retrying. Otherwise, resend only the events after the confirmed count.
