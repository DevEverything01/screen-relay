---
title: CLI reference
description: Commands and options for starting and controlling a screen-relay session.
---

Use `screen-relay` to start a desktop and control it:

```sh
screen-relay up -d
screen-relay screenshot screen.png
```

VM commands run on the Linux VM or Mac hosting the desktop, including a container or sandbox. Client commands also run remotely with a URL and token. [Global options](#global-options) include `--json`.

## VM commands

### up

Starts a desktop session and waits for it to be ready. On a machine that is not set up, it sets the machine up first. See [Getting started](/docs/getting-started#install-screen-relay).

```sh
screen-relay up -d --name demo --port 8084
```

For backend-specific usage, see [X11](/docs/x11), [Wayland](/docs/wayland), and [macOS](/docs/macos).

| Option | Meaning |
| --- | --- |
| `-d`, `--detach` | Run in the background. Otherwise, Ctrl+C stops the session. |
| `--config FILE` | YAML config. Default: `SCREEN_RELAY_CONFIG`, then `${XDG_CONFIG_HOME:-~/.config}/screen-relay/config.yaml` if present. |
| `--port N` | Listen port, 1–65535. Default `8080`. |
| `--desktop CMD` | `xfce`, `none`, or a command. Default: `xfce` on X11, `foot` on Wayland, or `none` when attaching. Always `none` on macOS. |
| `--display DISPLAY` | Attach to an existing display at its size. Not supported on macOS. |
| `--backend x11\|wayland\|macos` | On Linux, default `x11` when available, else `wayland`. Without a configured backend, a display without a colon selects Wayland. On macOS, `macos`. |
| `--output NAME` | Wayland output name, or a macOS display ID. Default: first output, or the main display. Not valid on X11. |
| `--public URL` | HTTPS origin. Generates a token. Requires a TLS proxy unless direct TLS is configured. |
| `--tls-cert FILE`, `--tls-key FILE` | Serve TLS directly. Both are required. |
| `--bind ADDR` | Listen address. Default `127.0.0.1`, or `0.0.0.0` with `--public`. Other addresses generate a token. |
| `--timeout S` | Engine and desktop readiness timeout in seconds. Default `30`; must be positive. |
| `--yes`, `-y` | Install missing packages without asking. Required when there is no terminal. |

Default display: 1280x720 at 60 fps. On macOS, screen-relay attaches to the existing display and ignores `display.resolution`. screen-relay does not stop an attached display. Treat viewer URLs containing `#token=` and JSON tokens as secrets. See [Configuration](/docs/configuration) and [Remote access](/docs/remote-access).

To become ready, a desktop command must open a window on X11 or a new Wayland display. Startup failures include the component's log. If the display, desktop, or engine exits later, the session stops; check `screen-relay status` and `screen-relay logs`. Foreground `up --json` prints after supervision ends; an interrupt prints no success document.

### down

Stops the session and its apps. Safe to repeat.

```sh
screen-relay down --name demo
```

The JSON outcome is `stopped` or `unchanged`.

### logs

Prints the last 200 lines of each log or one component.

```sh
screen-relay logs engine --follow
```

| Argument or option | Meaning |
| --- | --- |
| `component` | `display`, `dbus`, `desktop`, `engine`, or `apps`. Omit to show all. |
| `-f`, `--follow` | Follow new lines. Incompatible with `--json`. |

Detached sessions write `supervisor.log` in the [state directory](#state-directory).

### run

Starts an app on the session desktop and returns its process ID.

```sh
screen-relay run --name demo --restart -- mousepad notes.txt
```

| Option | Meaning |
| --- | --- |
| `--restart` | Restart the app whenever it exits, until the session stops. |

Put screen-relay options before `--`; everything after it goes to the app. Read output with `screen-relay logs apps`. Without `--restart`, a nonzero exit within one second reports `component_failed`. Restarts get new process IDs. Retry delays start at one second, double to 30 seconds, and reset after 60 seconds of uptime.

Apps share the display and D-Bus session when available; attached displays use the caller's environment. On Linux, apps run without ambient capabilities. On macOS, apps start in your user session without `DISPLAY`, `WAYLAND_DISPLAY`, or `XAUTHORITY`.

### doctor

Checks the VM or Mac and prints fixes for failed checks.

```sh
SCREEN_RELAY_BACKEND=wayland screen-relay doctor
```

| Option | Meaning |
| --- | --- |
| `--config FILE` | Load a YAML config, using the same default as `up`. |

The backend comes from `SCREEN_RELAY_BACKEND`, config, or the engine default. On macOS, doctor checks the macOS version, the engine, and the Screen Recording and Accessibility permissions. Failures exit 1; warnings do not. JSON checks include `name`, `status`, `detail`, and `fix`.

### install

Sets up the machine without starting a session. Safe to repeat.

```sh
screen-relay install --backend wayland --yes
```

| Option | Meaning |
| --- | --- |
| `--backend BACKEND` | Backend to set up: `x11`, `wayland`, or `all` on Linux; `macos` on macOS. Default: `x11` on Linux, `macos` on macOS. Also read from `SCREEN_RELAY_BACKEND` and the config file's `backend` key. |
| `--desktop COMMAND` | Same values as `up --desktop`. With the default `xfce` on x11, the XFCE packages are installed. With `none` or another command, they are skipped. |
| `--config FILE` | Read `backend` and `desktop` from this config file. |
| `--yes`, `-y` | Install packages without asking. Required when there is no terminal. |

The outcome is `installed` after it sets something up, or `unchanged` when nothing was missing. Adding a backend keeps the ones the engine already has. On Linux, package installation uses the system package manager and uses `sudo` unless you are root. See [Getting started](/docs/getting-started) for supported distributions.

## Client commands

Client commands share these options and the [client target rules](#client-target):

| Option | Meaning |
| --- | --- |
| `--url URL` | Engine origin. Default: the local session. Env: `SCREEN_RELAY_URL`. |
| `--token-file FILE` | Read a token from a file. Env: `SCREEN_RELAY_TOKEN_FILE`. See [Client target](#client-target). |
| `--timeout S` | Reply timeout in seconds. Default `10`; `0.001`–`2147483.647` in whole milliseconds. |

### status

Shows a local session or, with `--url`, a remote engine.

```sh
screen-relay status --name demo
```

| Option | Meaning |
| --- | --- |
| `--show-token` | Include the running local session's token. Hidden by default. |

Local states are `starting`, `ready`, `stopped`, and `failed`. Existing sessions exit 0 even when stopped or failed; missing sessions return `not_running`. JSON includes `session.running`, `url`, `localUrl`, `display`, `resolution`, `logs`, and, when running, `capabilities` or a `health` error. Other fields can include `backend`, `fps`, `desktop`, `tokenFile`, `tlsCert`, `ready`, `stopped`, `supervisor`, `ownsDisplay`, `runtimeDir`, and `waylandDisplay`. Failed sessions include `error`; remote status includes `url`, `capabilities`, and `metrics`.

### screenshot

Saves a PNG, including while a viewer is connected.

```sh
screen-relay screenshot /tmp/relay.png
```

| Argument | Meaning |
| --- | --- |
| `file` | Destination, default `screen.png`. `-` writes PNG bytes to stdout; incompatible with `--json`. |

### click

Clicks at the given screen coordinates.

```sh
screen-relay click 0.5 0.5 --button right
```

| Option | Meaning |
| --- | --- |
| `--button` | `left`, `middle`, or `right`. Default `left`. |

### move

Moves the pointer to the given screen coordinates.

```sh
screen-relay move 0.5 0.5
```

### scroll

Moves to a point and scrolls by whole wheel notches.

```sh
screen-relay scroll 0.5 0.5 --dy 3
```

| Option | Meaning |
| --- | --- |
| `--dx N` | Horizontal notches; positive is right. Default `0`. |
| `--dy N` | Vertical notches; positive is down. Default `0`. |

At least one value must be nonzero.

### key

Presses physical key combinations in order.

```sh
screen-relay key ctrl+l Enter
```

Join keys with `+`, for example `alt+Tab` or `ctrl++`. Modifiers are `ctrl`, `shift`, `alt`, and `super`; aliases include `control`, `meta`, `cmd`, and `win`. Keys include US-layout characters, navigation keys, and `F1`–`F24`.

### type

Types text using the remote keyboard layout.

```sh
screen-relay type "Hello, 世界"
```

| Option | Meaning |
| --- | --- |
| `--stdin` | Read text from stdin instead of an argument. |

An unavailable character returns `unsupported_input`.

### input

Sends 1–256 raw [input events](/docs/sdk#input-events) as a JSON array.

```sh
screen-relay input '[{"type":"keyDown","key":4},{"type":"keyUp","key":4}]'
```

| Option | Meaning |
| --- | --- |
| `--stdin` | Read the JSON array from stdin instead of an argument. |

### Input rules

Coordinates are fractions from `0` to `1`, measured from the top-left. Success means the engine applied the events, not that the app reacted; take a screenshot to check.

Only one input owner can send input: a viewer, SDK control session, or CLI. Batches use the engine's limit, up to 256 events; key combinations are never split. Keys and buttons are released after each batch. Another owner, a batch exceeding the 1024-event queue, or a session ending during input can return `busy`. No retries; partial failures report `data.applied`.

## Other commands

### skills

Reads the agent skills bundled with the CLI offline.

```sh
screen-relay skills list
screen-relay skills get core --full
screen-relay skills path core
```

| Option | Meaning |
| --- | --- |
| `--full` | Append references and templates to `skills get`. |

`list` is the default; `path` accepts an optional skill name. See [Agent skills](/docs/agent-skills).

### help

Shows help without starting a session.

```sh
screen-relay help click
screen-relay help --all --json
```

| Option | Meaning |
| --- | --- |
| `--all` | With `--json`, describe every command. |

## Global options

These options work before or after a command, but not after `--`:

| Option | Meaning |
| --- | --- |
| `-h`, `--help` | Show help. |
| `-v`, `--version` | Print the version. |
| `--json` | Print machine-readable output. |
| `--no-color` | Disable color. |
| `--name NAME` | Select a session; default `default`. Up to 64 characters, starting with a letter, digit, `_`, or `-`; later characters can also include `.`. |

Options accept `--name VALUE` or `--name=VALUE`. Boolean options accept `--no-OPTION`; `--` ends option parsing.

### Help layouts

Help detects agents and changes its layout. Set `SCREEN_RELAY_AGENT=1` or `SCREEN_RELAY_AGENT=0` to choose the agent or human layout. See [Agent-aware help](/docs/agent-skills#agent-aware-help).

## Client target

The target is `--url`, then `SCREEN_RELAY_URL`, then the ready local session. If the default session is missing and no name was selected, clients try `http://127.0.0.1:8080`. Without a URL, other client commands return `not_running` for an explicitly selected missing session or a stopped session. Local `status` never falls back.

The token comes from `--token-file`, then `SCREEN_RELAY_TOKEN_FILE`, then the local session only when no URL is set. Local `status` uses its stored token for health checks. Remote origins require HTTPS and a 64-character lowercase hexadecimal token. HTTP works only for `localhost` and `127.0.0.1`. URLs cannot contain a path, query, fragment, or credentials; redirects are refused. Local sessions trust their TLS certificate without a hostname check. See [Remote access](/docs/remote-access).

```sh
screen-relay screenshot desk.png --url https://desk.example.com --token-file ./token
```

## Output

Queries write to stdout; receipts and recovery steps go to stderr. When piped, `up` writes the viewer URL, `screenshot` the saved path, `run` the process ID, and input commands nothing. A viewer URL can contain a token.

Color follows `--no-color`, `NO_COLOR`, `FORCE_COLOR`, then terminal detection; `TERM=dumb` disables it.

## JSON output

`--json` writes a success document to stdout and structured errors to stderr. Success can include `warnings` and `next`. `doctor --json` writes checks to stdout even when a check fails. An interrupted command can exit without a document.

| Command | Success fields |
| --- | --- |
| `up` | `session` (`ready`, `name`, `url`, `viewer`, `token`, `display`, `waylandDisplay`, `xauthority`, `logs`, `pid`, `enginePid`, `bind`, `port`, `public`, `resolution`, `fps`), `outcome` |
| `down` | `session`, `outcome` |
| `status` | `session` |
| `screenshot` | `screenshot` (`path`, `width`, `height`, `bytes`), `outcome` |
| Input commands | `input.events`, `outcome` |
| `logs` | `logs`, keyed by component |
| `run` | `app.pid`, `app.command`, `outcome` |
| `doctor` | `checks`, `summary` |
| `install` | `install` (`backends`, `engine`), `outcome` |
| `skills` | `skills`, `skill`, or `path` |

### Error document

Errors contain `status` (`error` or `action_required`), `reason`, `message`, and optional `next` commands and `data`. Match `reason`, not `message`. Each `next` entry has `command` and `argv`; `data` can contain `component`, `log`, `logs`, `applied`, or `httpStatus`.

### Error reasons

| Reason | Meaning and action |
| --- | --- |
| `invalid_input` | Invalid value, URL, token, or event. Correct the input. |
| `invalid_option`, `unknown_command`, `missing_input` | Unknown option, command, or missing input. Check help. When `up` needs setup and there is no terminal, run `screen-relay install --yes` or pass `--yes` to `up`. |
| `missing_command` | `run` needs an app; place it after `--`. |
| `unauthorized` | Token missing or wrong. Check `--token-file`. |
| `forbidden` | Host or Origin rejected. Use public origin or loopback. |
| `unsupported_input` | Backend cannot produce the input. Change input or keyboard layout. |
| `busy` | Input is owned, the queue is full, or a screenshot is in progress. Release control or retry. |
| `unreachable` | Connection, DNS, or TLS failed. Check URL and certificate. |
| `timeout` | Startup or request timed out. Check logs or raise `--timeout`. |
| `not_running` | Missing session or logs, or stopped session. Start it or select another. |
| `not_found` | No running session for `run`, unknown skill or endpoint. Start the session or check the name. |
| `already_running` | Session name in use. Stop it or choose another. |
| `port_in_use` | Port occupied. Stop the process or choose another. |
| `component_failed` | Component or app failed. Read its logs. |
| `spawn_failed` | App could not start. Check its name and installation. |
| `missing_dependency` | A required program is missing. Run `screen-relay install`. |
| `unsupported_platform` | `up`, `down`, or `run` needs Linux or macOS. Run on the VM or Mac. |
| `invalid_config` | Invalid configuration. Correct the file and key named in the error. |
| `disconnected`, `io_error`, `protocol_error` | Connection lost, local I/O failed, or engine response invalid. Check the connection or reported file. |
| `canceled` | Interrupted. Retry if needed. |
| `internal` | Unexpected response or CLI error. Check logs and run `screen-relay doctor`. |

See [Troubleshooting](/docs/troubleshooting) for more fixes.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Runtime, network, permission, configuration, or missing-session failure. |
| `2` | Usage error, invalid value, or missing input. |
| `130` | Interrupted with Ctrl+C. A second interrupt exits immediately. |
| `128+n` | Terminated by signal `n`. |

## Environment variables

Options override environment variables, then config values, then defaults. Invalid values fail. See [Configuration](/docs/configuration) for keys and limits.

| Variable | Applies to |
| --- | --- |
| `SCREEN_RELAY_CONFIG` | `up` and `doctor` config file. |
| `SCREEN_RELAY_PORT`, `SCREEN_RELAY_BIND`, `SCREEN_RELAY_PUBLIC`, `SCREEN_RELAY_TLS_CERT`, `SCREEN_RELAY_TLS_KEY`, `SCREEN_RELAY_DESKTOP`, `SCREEN_RELAY_BACKEND` | Matching `up` options; `SCREEN_RELAY_BACKEND` also selects the backend for `doctor` and `install`. |
| `SCREEN_RELAY_RESOLUTION`, `SCREEN_RELAY_COMPOSITOR`, `SCREEN_RELAY_FPS`, `SCREEN_RELAY_BITRATE_MIN`, `SCREEN_RELAY_BITRATE_START`, `SCREEN_RELAY_BITRATE_MAX`, `SCREEN_RELAY_KEYBOARD_LAYOUT` | Display, stream, and keyboard settings. |
| `SCREEN_RELAY_URL`, `SCREEN_RELAY_TOKEN_FILE` | Client URL and token file. |
| `SCREEN_RELAY_AGENT` | Help layout: `1` for agent, `0` for human. |
| `NO_COLOR`, `FORCE_COLOR` | Output color. |

### State directory

Session files and logs are in `${XDG_STATE_HOME:-~/.local/state}/screen-relay/<name>/`. The directory has mode `0700`; its token file has mode `0600`.
