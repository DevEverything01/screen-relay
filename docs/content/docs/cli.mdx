`relay` is one command (Node 26 or newer, dependencies bundled). Run `relay --help` for the list, `relay help <command>` or `relay <command> --help` for one command, and `relay <command> --help --json` for machine-readable options. In this page "the VM" is the Linux machine that shows the desktop; see [Architecture](/docs/architecture) for how the pieces fit.

| Group | Commands | Where they run |
| --- | --- | --- |
| [VM commands](#vm-commands) | `up`, `down`, `logs`, `run`, `doctor` | On the VM. `up`, `down`, and `run` fail with `unsupported_platform` off Linux. |
| [Client commands](#client-commands) | `status`, `screenshot`, `click`, `move`, `scroll`, `key`, `type`, `input` | On the VM, or anywhere with `--url` and a token. |
| [Other commands](#other-commands) | `skills`, `help` | Anywhere. They never contact an engine. |

Options common to every command are in [Global options](#global-options). Client commands also share the [client target rules](#client-target).

## VM commands

### up

Starts or attaches to a display, starts the desktop when enabled and the engine, then supervises the session. Without `-d` it runs in the foreground and Ctrl+C stops the session.

```sh
relay up [-d] [--name N] [--config FILE] [--port N] [--desktop xfce|none|CMD] [--display DISPLAY]
         [--backend x11|wayland] [--output NAME] [--public HTTPS_URL] [--tls-cert F --tls-key F]
         [--bind ADDR] [--timeout S]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `-d`, `--detach` | off | Run in the background. Returns once ready, or with the startup error. |
| `--config FILE` | `$RELAY_CONFIG`, else `${XDG_CONFIG_HOME:-~/.config}/relay/config.yaml` when it exists | YAML config file. Flags beat the file. See [Configuration](/docs/configuration). |
| `--port N` | `8080` | Listen port. Env: `RELAY_PORT`. |
| `--desktop` | `xfce` (x11) or `foot` (wayland); `none` with `--display` | `xfce`, `none` (no desktop), or a command such as `openbox`. Runs under `dbus-run-session` when it is installed. Env: `RELAY_DESKTOP`. |
| `--display DISPLAY` | new display | Attach to an existing display. On x11, an X display such as `:0`, using your `XAUTHORITY`. On wayland, a Wayland socket name such as `wayland-1`, which needs `XDG_RUNTIME_DIR`. relay never stops or changes a display it did not start. It uses that display's size. |
| `--backend x11\|wayland` | `x11` when the engine has it, else `wayland` | Display server to run the desktop on. Env: `RELAY_BACKEND`. See [Wayland](/docs/wayland). |
| `--output NAME` | first output | Wayland output to capture, by name. For a screen larger than 1920x1080, see [Wayland](/docs/wayland) to create a headless output. |
| `--public URL` | off | Public HTTPS origin. Binds `0.0.0.0` unless `--bind` is set, generates a token, and allows that origin. It expects a TLS proxy in front unless `--tls-cert` is given. See [Remote access](/docs/remote-access). Env: `RELAY_PUBLIC`. |
| `--tls-cert F`, `--tls-key F` | off | Serve TLS directly. Both are required together. Env: `RELAY_TLS_CERT`, `RELAY_TLS_KEY`. |
| `--bind ADDR` | `127.0.0.1` | Listen address. Any other address generates a token. Env: `RELAY_BIND`. |
| `--timeout S` | `30` | Seconds to wait for readiness. |

Settings that only exist in the config file (resolution, frame rate, bitrate, keyboard layout) are listed in [Configuration](/docs/configuration) and [Environment variables](#environment-variables). The default resolution is 1280x720.

```sh
relay up -d --name demo --port 8084
```

Prints this receipt on stderr (stdout when piped is only the viewer URL):

```console
$ relay up -d --name demo --port 8084
✓ Started         demo
  Viewer          http://127.0.0.1:8084
  Display         :1
  Resolution      1280x720 at 60 fps
  Logs            /home/relay/.local/state/relay/demo

  Stop it:
    relay down --name demo
```

With `--public` the viewer line carries the token (shortened here):

```console
$ relay up -d --name pub --port 8082 --public https://desk.example.com --desktop none
✓ Started         pub
  Viewer          https://desk.example.com/#token=<TOKEN>
  Display         :1
  Resolution      1280x720 at 60 fps
  Logs            /home/relay/.local/state/relay/pub

  Stop it:
    relay down --name pub
```

The TLS proxy line is left out with `--tls-cert`. With a non-loopback `--bind` and no `--public`, `up` instead prints `Listening on ADDR:PORT; reach it through a loopback port publish or SSH tunnel.` Treat a viewer URL with `#token=` as a secret.

Ready means:

1. The engine this run started has logged its ready line, and `GET /screenshot.png` returns a PNG.
2. On X11, the desktop shows its own signal on the display: for `xfce`, a window manager (`_NET_SUPPORTING_WM_CHECK`) with at least one managed window (`_NET_CLIENT_LIST`); for a custom command, at least one window on the root. When relay starts sway, sway must report at least one window. With `--display` on Wayland, the desktop readiness check is skipped. Skipped for `--desktop none`.

If that does not happen within `--timeout`, `up` fails with `timeout`. If a component exits first, it fails with `component_failed`. Both errors name the component and include its log tail. After ready, the supervisor keeps watching. If the display, desktop, or engine exits later, the whole session stops and `status` shows the error. Apps started with `run` are not supervised; they stop with `down`.

`up` prints the token once, when there is one ([Tokens](/docs/remote-access#tokens)).

`up -d --json` prints one object when ready. Foreground `up --json` defers its result until supervision ends, so a later engine failure leaves stdout empty. Interrupting it stops the session without printing a success document.

```json
{"session":{"ready":true,"name":"two","url":"http://127.0.0.1:8081","viewer":"http://127.0.0.1:8081","token":null,"display":":1","xauthority":"/home/relay/.local/state/relay/two/Xauthority","logs":"/home/relay/.local/state/relay/two","pid":266,"enginePid":272,"bind":"127.0.0.1","port":8081,"public":false,"resolution":"1280x720","fps":60},"outcome":"started"}
```

| Session field | Meaning |
| --- | --- |
| `url` | The `--public` origin, else the local URL. |
| `viewer` | `url/#token=TOKEN` when there is a token, else `url`. |
| `token` | The token, or `null`. |
| `display`, `xauthority` | X display and its cookie file. With `--display`, your `XAUTHORITY` or `null`. |
| `logs` | State directory. |
| `pid`, `enginePid` | Supervisor and engine process IDs. |
| `bind`, `port`, `public` | Listen address, port, and whether `--public` was set. |
| `resolution`, `fps` | Display size and capture frame rate. |

### down

Stops the session and the processes it started, including apps started with `run`. Safe to run twice.

```sh
relay down [--name N]
```

```sh
relay down --name demo
```

`--json` prints `{"session":{"name":"default"},"outcome":"stopped"}`. The outcome is `unchanged` when nothing was running.

### logs

Prints the last 200 lines of one component's log, or of every log that exists.

```sh
relay logs [component] [--name N] [-f|--follow]
```

| Argument or option | Meaning |
| --- | --- |
| `component` | `display`, `dbus`, `desktop`, `engine`, or `apps`. Omit it to print every log that exists. |
| `-f`, `--follow` | Keep printing new lines. Cannot be combined with `--json`. |

```sh
relay logs engine --follow
```

`--json` wraps the logs by component, for example `{"logs":{"display":"...","desktop":"...","engine":"..."}}`. A session started with `-d` also writes its own startup and supervision messages to `supervisor.log` in the [state directory](#state-directory).

### run

Starts an app on the session's desktop and returns its pid. Use `--` before the app so its own flags pass through unchanged.

```sh
relay run -- <app> [args]... [--name N] [--restart]
```

| Option | Meaning |
| --- | --- |
| `--restart` | Start the app again whenever it exits, until the session stops. |

The app gets the desktop's display and its D-Bus session bus, X authority, runtime, config, cache, and ICE authority settings when present. On Wayland it also gets `WAYLAND_DISPLAY`. Sharing the bus lets accessibility clients find the app. With `up --display :N`, apps inherit the caller's session environment instead. Apps run with ambient capabilities cleared and stop with `relay down`. Their output goes to `relay logs apps`.

With `--restart`, retries wait 1 second, doubling up to 30 seconds. The delay resets after the app stays up for 60 seconds. Each restart is recorded in `relay logs apps`. The returned pid is the first app process, not its watcher; it changes on restart. Without the flag, apps start once.

```console
$ relay run -- mousepad notes.txt
✓ Started         mousepad
  PID             4412
  Display         :0
  Logs            ~/.local/state/relay/default/apps.log
```

`--json` prints `{"app":{"pid":4412,"command":["mousepad","notes.txt"]},"outcome":"started"}`. A missing app is `missing_command`; an app that cannot start is `spawn_failed`; an app that exits within a second is `component_failed` with `component` set to `apps`.

### doctor

Checks this machine and prints the fix command for each problem. Takes only the [global options](#global-options).

```sh
relay doctor
```

Exits 1 if any check fails; `warn` does not fail. `--json` prints `{"checks":[...],"summary":{...}}`. Each check has `name`, `status` (`ok`, `warn`, or `fail`), `detail`, and `fix`.

The backend comes from `RELAY_BACKEND`, then the config file's `backend` key, then the engine default (X11 when the engine includes it, Wayland otherwise). `--backend` does not apply here, so check a Wayland setup with `RELAY_BACKEND=wayland relay doctor`.

| Check | What it looks at |
| --- | --- |
| `platform` | Linux. Off Linux this is the only check, and it fails. |
| `user` | Root or the UID (information only). |
| `node` | Node 26 or newer. |
| `setpriv` | Program is on `PATH`; used to start apps without ambient capabilities. |
| `home`, `state dir` | `HOME` and the state directory are writable. |
| `engine` | `relay-engine` is found and runs. |
| `libx264` | The x264 library is installed. |
| `Xvfb`, `xauth`, `xprop`, `xwininfo`, `xdpyinfo` | Programs are on `PATH` (x11). |
| `sway`, `Xwayland`, `foot` | Programs are on `PATH` (wayland). |
| `setxkbmap` | Program is on `PATH` (x11); relay uses it when the keyboard layout is not `us`. |
| `dbus-run-session` | Present (warn only). |
| `xfce4-session` | Present (warn only, x11 only). |
| `/tmp/.X11-unix` | Usable by Xvfb (x11). |
| `port` | `127.0.0.1:8080` is free (warn only). |
| `X extensions` | A scratch Xvfb offers XTEST, DAMAGE, XFIXES, and MIT-SHM (x11). |
| `ambient caps` | Inherited ambient capabilities. `up` and `run` clear them; GTK apps started from another shell with them set crash on icons. |
| `icon decoding` | gdk-pixbuf decodes a PNG and an SVG under your user with ambient capabilities cleared. On failure it may suggest `glycin-loaders` or report blocked user namespaces for bubblewrap. Missing gdk-pixbuf or its tools and SVG decoding failures are warnings; PNG decoding failures fail the check. |

When a fix uses system packages, it names your distribution's package manager (apt, dnf, pacman, or apk). On an unrecognized distribution, it lists the package names instead.

## Client commands

Client commands talk to an engine over HTTP. All of them take the options below, which are not repeated per command. Rules for choosing the engine and token are in [Client target](#client-target).

| Option | Default | Meaning |
| --- | --- | --- |
| `--url URL` | local session | Engine origin. Env: `RELAY_URL`. |
| `--token-file FILE` | local session token | File holding the token. Env: `RELAY_TOKEN_FILE`. |
| `--timeout S` | `10` | Seconds to wait for a reply. |

Input commands (`click`, `move`, `scroll`, `key`, `type`, `input`) print nothing on success, print `{"input":{"events":1},"outcome":"sent"}` with `--json`, and follow the [input rules](#input-rules). Success means the engine applied the events, not that the application reacted; take a screenshot to confirm.

### status

Shows the local session and asks its engine for its capabilities, or shows a remote engine when you pass `--url`.

```sh
relay status [--name N] [--url URL] [--token-file F] [--timeout S] [--show-token]
```

| Option | Meaning |
| --- | --- |
| `--show-token` | Include the session token in the output. Hidden by default. |

```console
$ relay status
  Session         default
  State           ready
  URL             http://127.0.0.1:8080
  Display         :0
  Resolution      1280x720
  Fps             60
  Logs            /home/relay/.local/state/relay/default
```

Exits 0 for an existing session in any state, including stopped or failed. A missing session exits 1 with `not_running`. `--json` for a running session (capabilities trimmed):

```json
{"session":{"name":"demo","state":"ready","logs":"/home/relay/.local/state/relay/demo","display":":1","xauthority":"/home/relay/.local/state/relay/demo/Xauthority","running":true,"capabilities":{"version":1,"backend":"x11","width":1280,"height":720,"fps":60}}}
```

| Field | Meaning |
| --- | --- |
| `state` | `starting`, `ready`, `stopped`, or `failed`. |
| `running` | `true` only when `state` is `ready` and the supervisor is alive. |
| `url`, `localUrl` | Public or local URL, and the URL local clients use. |
| `backend` | `x11` or `wayland`. |
| `waylandDisplay` | Wayland socket, such as `wayland-1`. Only on wayland. |
| `runtimeDir` | Runtime directory of the sway session. Only on wayland when relay starts sway. Deleted by `down`. |
| `display`, `xauthority`, `ownsDisplay`, `desktop` | X display, cookie file, whether `up` started the display, and the desktop setting. |
| `resolution`, `fps` | Display size and stream frame rate. With `--display`, the size comes from the existing display. |
| `bind`, `port`, `tlsCert` | Listen address, port, and TLS certificate path or `null`. |
| `tokenFile` | Token path, present only when there is a token. |
| `token` | Present only with `--show-token` while running. |
| `supervisor`, `logs` | Supervisor PID and start time; state directory. |
| `ready`, `stopped` | Unix times. |
| `capabilities` | Engine capabilities when running ([Protocol](/docs/protocol#get-capabilities)). |
| `health` | Error object when running but the engine did not answer. |
| `error` | Error object after a failure, with `component` and `log`. |

With `--url`, shows a remote engine instead. `--json` wraps `url`, `capabilities`, and `metrics` in `session`:

```console
$ relay status --url http://127.0.0.1:18200 --token-file ./token
  URL             http://127.0.0.1:18200
  Backend         x11
  Resolution      1280x720
```

### screenshot

Saves a PNG of the screen. Works while a viewer is connected.

```sh
relay screenshot [file] [--url URL] [--token-file FILE] [--timeout S]
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `file` | `screen.png` | Destination path. `-` writes the PNG bytes to stdout and cannot be combined with `--json`. |

```sh
relay screenshot /tmp/relay.png
```

When piped, prints only the saved path. `--json` prints `{"screenshot":{"path":"/tmp/relay.png","width":1280,"height":720,"bytes":12345},"outcome":"saved"}`.

### click

Clicks at a point. Coordinates are fractions of the screen from 0 to 1, from the top-left.

```sh
relay click <x> <y> [--button left|middle|right]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--button` | `left` | `left`, `middle`, or `right`. |

```sh
relay click 0.5 0.5
```

### move

Moves the pointer.

```sh
relay move <x> <y>
```

```sh
relay move 0.5 0.5
```

### scroll

Moves to a point, then scrolls.

```sh
relay scroll <x> <y> [--dx N] [--dy N]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--dy N` | `0` | Vertical wheel notches. Positive scrolls down. |
| `--dx N` | `0` | Horizontal wheel notches. Positive scrolls right. |

At least one of `--dx` and `--dy` must be nonzero.

```sh
relay scroll 0.5 0.5 --dy 3
```

### key

Presses each key combination in order. Combos are `+`-joined: `ctrl+l`, `Enter`, `alt+Tab`, `ctrl++`.

```sh
relay key <combo>...
```

Modifiers are `ctrl`, `shift`, `alt`, and `super` (also `control`, `meta`, `cmd`, `win`). Keys are physical keys: a US-layout character or a name such as `Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, `Up`, `Down`, `Left`, `Right`, or `F1` to `F24`.

```sh
relay key ctrl+l
```

### type

Types text, one text event per Unicode scalar value. The engine produces each character using the current remote keyboard layout, or reports `unsupported_input` when it cannot. Unlike `key`, it does not assume a US layout.

```sh
relay type <text>
relay type --stdin
```

| Option | Meaning |
| --- | --- |
| `--stdin` | Read the text from stdin instead of the argument. |

```sh
relay type "Hello, 世界"
```

### input

Sends a JSON array of raw input events, with the same schema as the [SDK](/docs/sdk#input-events). It accepts 1 to 256 events.

```sh
relay input <json>
relay input --stdin
```

| Option | Meaning |
| --- | --- |
| `--stdin` | Read the JSON array from stdin instead of the argument. |

```sh
relay input '[{"type":"keyDown","key":4},{"type":"keyUp","key":4}]'
```

The SDK sends each raw event as its own batch and checks the engine's advertised `max_input_batch`.

### Input rules

- X and Y are fractions of the screen from 0 to 1, from the top-left.
- Input goes to the engine as `POST /input` batches limited by the capabilities `max_input_batch` value (currently 256 events; [Protocol](/docs/protocol#post-input)).
- `type` sends one text event per character and `key` one group per combo. Events are packed into as many batches as needed and a combo is never split.
- Only one input owner can send input at a time: a viewer, an SDK control session, or the CLI. If another owner holds control, the input queue already holds 1024 events, or the session ends between batches, the batch fails with `busy` (HTTP 409). It is never retried. Another owner can take control between batches, so a long `type` or `key` can stop partway, and a batch still queued when the session ends fails as `busy` after applying a prefix. The JSON error then carries `data.applied`, the number of events already applied.
- Held keys and buttons are released at the end of each batch, and when it fails.

## Other commands

### skills

Serves the agent skills that ship with the CLI, so their instructions match the installed version. Works offline.

```sh
relay skills list
relay skills get <name> [--full] [--json]
relay skills path [name]
```

```sh
relay skills get core
```

See [Agent skills](/docs/agent-skills) for the output shapes, the shipped skills, and the core workflow.

### help

Shows help for the CLI or one command.

```sh
relay help [command] [--all]
```

`--all --json` returns every command. See [Help layouts](#help-layouts).

## Global options

These work on every command, before or after the command name.

| Option | Meaning |
| --- | --- |
| `-h`, `--help` | Show help. |
| `-v`, `--version` | Print only the version, `0.1.0`. With `--json`, `{"version":"0.1.0"}`. |
| `--json` | Print one JSON document. See [JSON output](#json-output). |
| `--no-color` | Disable color. |
| `--name NAME` | Session name, default `default`. Up to 64 characters. The first character is a letter, digit, `_`, or `-`; later characters may also be `.`. |

Options accept `--name <NAME>` and `--name=NAME`. `--` ends option parsing. Boolean options accept `--no-<OPTION>`. Unknown options, commands, and extra positionals fail before any work, with at most one close suggestion and a help command. Options do not accept prefix matching. The only short options are `-h`, `-v`, `-f` (`logs --follow`), and `-d` (`up --detach`).

### Help layouts

Help works offline, writes to stdout, and exits 0 without starting anything. `relay <command> --help --json` returns `path`, `summary`, `runsOn` (`vm`, `client`, or `anywhere`), `arguments`, `options`, `examples`, `notes`, and the result schema. `relay help --all --json` returns every command.

Help has two layouts. For people, root help shows the version, usage, three sections (`VM commands`, `Client commands`, `Other commands`), and examples. Command help adds where the command runs, alphabetical options with defaults, and examples. Color is used only when stdout is a terminal and color is allowed, so a pipe, `NO_COLOR`, `--no-color`, or `TERM=dumb` prints plain text.

When an AI agent is detected, help uses a descriptive plain-text layout: usage, a `Start here (for AI agents)` block on root help that points to `relay skills get core`, where the command runs, arguments, options, global options, examples, notes, and a documentation link. Detection affects help only; every other command behaves the same. Set `RELAY_AGENT=1` or `RELAY_AGENT=0` to force a layout. See [Agent skills](/docs/agent-skills#agent-aware-help).

## Client target

Client commands pick the engine in this order:

1. `--url`, else `RELAY_URL`.
2. The local session named by `--name`, if it is ready: its URL, token file, and TLS certificate. The session certificate is trusted without a hostname check, as a local session needs.
3. `http://127.0.0.1:8080` only when no session was explicitly selected and the default session does not exist.

An explicitly selected missing session, a stopped session, or one whose supervisor is gone fails with `not_running`. Pass `--url` to target an engine without a local session.

The token comes from `--token-file`, else `RELAY_TOKEN_FILE`, else the local session. The file holds the 64-character token. The client only reads it, so its mode does not matter. See [Tokens](/docs/remote-access#tokens).

URL rules: an origin only (no path, query, or credentials). Plain HTTP only for `localhost` and `127.0.0.1`; other hosts need HTTPS and a token. Redirects are refused.

```sh
relay screenshot desk.png --url https://desk.example.com --token-file ./token
```

## Output

Queries write data to stdout. Mutations write receipts and next steps to stderr. When stdout is piped, `up` writes only the viewer URL (including `#token=` when needed), `screenshot` writes only the saved path, and input commands write nothing.

Terminal receipts use `✓`, `!`, and `✗` in column 0, text from column 2, and label values from column 18. Non-terminal stderr or `TERM=dumb` uses plain words and no color. Color precedence is `--no-color`, nonempty `NO_COLOR`, `FORCE_COLOR` (`0` disables it), then detection for each stream. Human errors are a headline, context, and one recovery command on stderr, with no stack trace.

## JSON output

`--json` writes exactly one JSON document and a newline to stdout, pretty-printed with two spaces on a terminal and compact otherwise. A successful JSON command leaves stderr empty. A failure leaves stdout empty and writes one compact error document to stderr. Keys use camelCase. Success may include `warnings: [{reason, message}]` and `next: [{command, argv}]`.

| Command | JSON success shape |
| --- | --- |
| `up` | `{"session":{...},"outcome":"started"}` |
| `down` | `{"session":{...},"outcome":"stopped"}` or `"unchanged"` |
| `status` | `{"session":{...}}` |
| `screenshot` | `{"screenshot":{"path":"<PATH>","width":1280,"height":720,"bytes":12345},"outcome":"saved"}` |
| `click`, `move`, `scroll`, `key`, `type`, `input` | `{"input":{"events":1},"outcome":"sent"}` |
| `doctor` | `{"checks":[...],"summary":{...}}` |
| `logs` | `{"logs":{"<component>":"<text>"}}` |
| `run` | `{"app":{"pid":4412,"command":["<APP>","<ARG>"]},"outcome":"started"}` |
| `skills` | `{"skills":[...]}`, `{"skill":{...}}`, or `{"path":"..."}` |

### Error document

```json
{"status":"error","reason":"not_running","message":"No session named \"default\"","next":[{"command":"relay up -d","argv":["relay","up","-d"]}]}
```

| Field | Meaning |
| --- | --- |
| `status` | `error`, or `action_required` when different input can unblock the command before it had any effect. |
| `reason` | Stable snake_case code. Match this, not the message. |
| `message` | One-line headline. |
| `next` | Optional recovery commands. `command` is the full command line and `argv` is the same command split, starting with `relay`. |
| `data` | Optional context, such as `component` and `logs` after a component failure, `applied` after a partial input failure, or `httpStatus` from the engine. |

A failed start, for example a desktop command that exits:

```console
$ relay up -d --name bad --port 8085 --desktop false --json
{"status":"error","reason":"component_failed","message":"Failed to start the desktop. It exited with code 1.","next":[{"command":"relay logs desktop --name bad","argv":["relay","logs","desktop","--name","bad"]}],"data":{"component":"desktop","logs":"/home/relay/.local/state/relay/bad"}}
```

### Error reasons

| Reason | Meaning |
| --- | --- |
| `invalid_input` | Invalid argument, JSON, input event, key combo, port, session name, URL, public origin, TLS, or token file; also an invalid engine input batch (HTTP 400/413). |
| `invalid_option`, `unknown_command`, `missing_input` | Unknown option or command, or required input missing (exit 2). |
| `unauthorized` | Token missing or wrong (HTTP 401). |
| `forbidden` | Host or Origin rejected (HTTP 403). |
| `unsupported_input` | The backend cannot produce a character or apply the requested input (HTTP 422). |
| `busy` | A viewer or SDK session holds control (HTTP 409), or a screenshot is already running (HTTP 503). Never retried. |
| `unreachable` | Cannot connect to the URL. The message names the cause: `Connection refused.`, `The host name did not resolve.`, or `The TLS certificate was rejected.` |
| `timeout` | No reply within `--timeout`, or `up` did not become ready in time (`component` and `log` set). |
| `not_running` | No session or logs with that name. |
| `not_found` | No running session for `run`, no skill with that name, or an unknown engine endpoint. |
| `missing_command` | `run` was given no app (exit 2). |
| `spawn_failed` | `run` could not start the app. |
| `already_running` | A session with that name is already running. |
| `port_in_use` | The requested listen port is occupied. |
| `component_failed` | display, desktop, engine, or the background supervisor exited or could not start (`component`, `log`, and `logs` are set), or an app started by `run` exited within a second (`component` is `apps`, `log` is set, no `logs`). |
| `missing_dependency` | A required host program or the engine binary is missing. Failed app spawns use `spawn_failed`. |
| `unsupported_platform` | `up`, `down`, or `run` was run off Linux. |
| `invalid_config` | Invalid configuration; the message names the file and key path. |
| `disconnected`, `io_error`, `protocol_error` | Lost session, failed local I/O, or an invalid engine response. |
| `canceled` | Interrupted operation (exit 130). |
| `internal` | Unexpected engine response or a CLI bug. |

Input commands that fail after some batches report `data.applied` (events already applied). The SDK exposes the same snake_case `reason` through `RelayError.reason` ([SDK errors](/docs/sdk#errors)). For fixes by reason, see [Troubleshooting](/docs/troubleshooting).

### Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success. |
| 1 | Runtime, network, permission, configuration, or missing-session failure. |
| 2 | Usage error, invalid value, or missing input. |
| 130 | Interrupted with Ctrl+C. A foreground `up` stops its session on the first interrupt; a second interrupt exits immediately. |
| 128+n | Terminated by signal n. |

## Environment variables

Precedence is an explicit option, its `RELAY_*` variable, the config file, then the default. An explicit invalid value fails instead of falling back. Config validation reports all problems before starting any process.

| Variable | Applies to |
| --- | --- |
| `RELAY_CONFIG` | `up --config`; otherwise `${XDG_CONFIG_HOME:-~/.config}/relay/config.yaml` when present. |
| `RELAY_PORT`, `RELAY_BIND`, `RELAY_PUBLIC`, `RELAY_TLS_CERT`, `RELAY_TLS_KEY`, `RELAY_DESKTOP` | The matching `up` options. |
| `RELAY_BACKEND` | `up --backend`, and the backend that `relay doctor` checks. Config key `backend`. |
| `RELAY_RESOLUTION`, `RELAY_FPS`, `RELAY_BITRATE_MIN`, `RELAY_BITRATE_START`, `RELAY_BITRATE_MAX`, `RELAY_KEYBOARD_LAYOUT` | The matching config keys (`display.resolution`, `stream.fps`, `stream.bitrate.*`, `keyboard.layout`). See [Configuration](/docs/configuration). |
| `RELAY_URL` | Client `--url`. |
| `RELAY_TOKEN_FILE` | Client `--token-file`. |
| `RELAY_AGENT` | Help layout: `1` for the agent layout, `0` for the human layout. No other output changes. |
| `NO_COLOR`, `FORCE_COLOR` | Color, as described under [Output](#output). |

### State directory

Each session keeps its files in `${XDG_STATE_HOME:-~/.local/state}/relay/<name>/` (mode 0700): `session.json`, `token` (0600), `display.log`, `dbus.log` when relay starts its own bus, `desktop.log`, `engine.log`, `apps.log` (after `run`), and `supervisor.log` (`-d` only).

## install.sh

```sh
./install.sh [--prefix DIR] [--backend x11|wayland|all] [--no-desktop] [--no-deps] [--client-only]
```

| Flag | Meaning |
| --- | --- |
| `--prefix DIR` | Absolute install location. Default `$PREFIX`, else `~/.local`. |
| `--backend x11\|wayland\|all` | Packages to install and engine backends to build. Default `x11`. `all` installs both, and the final `relay doctor` checks x11. |
| `--no-desktop` | Skip the XFCE package group. |
| `--no-deps` | Skip package installation. Dependencies must already be present. |
| `--client-only` | Install only the CLI, for example on a laptop. Works off Linux. |

Automatic dependencies need root or passwordless sudo. The installer reads `ID` and `ID_LIKE` from `/etc/os-release` to pick a package manager: apt for Debian and Ubuntu, dnf for Fedora, pacman for Arch Linux (including Manjaro and Omarchy), and apk for Alpine. On any other distribution it exits and names the supported ones.

With the default `--backend x11`, on Debian and Ubuntu it installs the build tools, the X11 libraries, `libx264`, `libwebsockets`, `xvfb`, `xauth`, `x11-utils`, `x11-xkb-utils`, `util-linux` (for `setpriv`), and with the desktop: D-Bus, XFCE (`xfce4-session`, `xfwm4`, `xfce4-panel`, `xfdesktop4`, `xfce4-settings`, `thunar`, `xfce4-terminal`), and `glycin-loaders` when the distribution has it. Fedora, Arch and Alpine install the equivalent packages under their own names. With `--backend wayland`, it installs the Wayland libraries, `sway`, `Xwayland`, and `foot` instead of the X11 packages and XFCE. With `--backend all`, it installs both sets. On Ubuntu, if `libx264` is not available, it adds the universe component to the Components lines in `/etc/apt/sources.list.d/ubuntu.sources` and runs `apt-get update`. It stops if that file does not exist or `libx264` is still unavailable after the update. On Fedora, it stops if the x264 package is unavailable (see [Getting started](/docs/getting-started)). On Arch Linux it runs a full upgrade (`pacman -Syu`) before it installs anything.

It uses the system `node` when it is 26 or newer; otherwise it downloads the version pinned in `.node-version` from `https://nodejs.org/dist/`. On Alpine, which uses musl, it downloads from `https://unofficial-builds.nodejs.org/` instead. It checks the archive against that release's `SHASUMS256.txt` and unpacks it in `<prefix>/lib/relay/node`. It runs `npm ci` and `npm run build` with that Node. It is safe to re-run.

It installs the CLI as `<prefix>/lib/relay/relay.mjs` with a `<prefix>/bin/relay` launcher that prefers `<prefix>/lib/relay/node`, the engine, and the built viewer in `<prefix>/lib/relay/` (the engine is linked as `<prefix>/bin/relay-engine`). When `<prefix>/bin` is not on `PATH` it prints:

```text
Not on PATH; add it with: export PATH="<prefix>/bin:$PATH"
```

A full install ends by running `relay doctor` and exits non-zero if doctor finds a failure.
