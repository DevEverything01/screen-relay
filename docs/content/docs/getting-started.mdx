title: Getting started
description: Start a Linux desktop and control it from a browser or the CLI.
---

Start a desktop on a Linux VM, open it in your browser, and control it with relay.

## Prerequisites

- A Linux VM, container, or sandbox with Git and root or passwordless `sudo`.
- Debian, Ubuntu, Fedora, Arch Linux, or Alpine for automatic dependency installation. On another distribution, install the dependencies yourself and add `--no-deps` to the install command.
- SSH access to the VM from your laptop.
- A browser with H.264 WebCodecs, such as current Chrome, Edge, or Safari.

## 1. Install relay

On the VM, clone the repository and run the installer:

```sh
git clone https://github.com/vercel-labs/relay.git
cd relay
./install.sh --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
```

The installer installs the dependencies, builds and installs relay, and runs `relay doctor`. It exits with an error if a check fails. Add the `export` line to your shell profile to keep relay on your `PATH`. The installer needs Node 26 or newer and npm; on Linux x64 and arm64, it downloads its pinned version if needed.

On Fedora, if the installer asks for RPM Fusion Free, run the printed command and retry. For a user with `sudo`, the command is:

```sh
sudo dnf -y install https://download1.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm
```

For Wayland or Docker, see [Wayland](/docs/wayland) or [Docker](/docs/docker). The [CLI reference](/docs/cli) lists all installer options.

## 2. Start a session

On the VM, run:

```sh
relay up -d
```

Relay starts the desktop and prints a viewer link when it is ready. By default, the session is named `default` and the desktop is 1280x720 at 60 fps. See [Configuration](/docs/configuration) to change the resolution or frame rate, or [Troubleshooting](/docs/troubleshooting) if startup fails.

## 3. Open the viewer

The default session listens on `127.0.0.1:8080` on the VM. From your laptop, forward the port over SSH, replacing `user@your-vm` with your login and VM address:

```sh
ssh -N -L 8080:127.0.0.1:8080 user@your-vm
```

Leave the tunnel running and open the viewer link printed by `relay up`. You should see the desktop. The default loopback session needs no token. If a link contains `#token=`, keep the whole link secret.

Use HTTPS or `http://127.0.0.1` for the viewer's secure context. See [Remote access](/docs/remote-access) for other ways to connect.

## 4. Control it from the VM

On the VM, start a terminal on the default X11 desktop:

```sh
relay run -- xfce4-terminal
```

The command prints the process ID. Wait for the terminal to appear in the viewer, then close the viewer tab before sending input. Only one controller can send input at a time, and another gets `busy`.

```sh
relay screenshot screen.png
relay click 0.5 0.5
relay type "echo hello"
relay key Enter
relay screenshot after.png
```

The click is at the center of the screen. If the terminal is elsewhere, replace `0.5 0.5` with a point inside it; coordinates are fractions from 0 to 1 measured from the top-left. Reopen the viewer to check for `hello`. The screenshots are saved on the VM.

Ask an agent on the VM to run:

```sh
relay skills get core
```

This prints the agent workflow for screenshots and input. See [Agent skills](/docs/agent-skills) for more.

## 5. Stop the session

On the VM, run:

```sh
relay down
```

Relay confirms the session has stopped. This also stops apps started with `relay run`.
