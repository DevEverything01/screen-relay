title: Getting started
description: Install relay on a Linux VM, start a session, open the viewer, and control the desktop from the VM and from your laptop.

This guide takes you from a Linux VM to a desktop you can see in a browser and control from the command line, first on the VM and then from your laptop.

## Prerequisites

- A Linux VM to run the desktop. A container or sandbox works too.
- A supported distribution for automatic dependency installation: Debian 13, Ubuntu 24.04 or 26.04, Fedora 44, Arch Linux (including Manjaro and Omarchy), or Alpine 3.24. On another distribution, install the dependencies yourself and pass `--no-deps` to the installer.
- Root or passwordless `sudo`, so the installer can install packages.
- Node 26 or newer. If it is missing, the installer downloads the pinned version.
- A browser with H.264 WebCodecs for the viewer: current Chrome, Edge, or Safari.

## 1. Install relay

On the VM, from a clone of the repository:

<Callout title="x264 on Fedora">
  On Fedora, RPM Fusion Free provides the x264 library relay needs. If the x264 package
  is unavailable, the installer prints this command and stops. Run it, then run
  `./install.sh` again:

  ```sh
  sudo dnf -y install https://download1.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm
  ```
</Callout>

```sh
./install.sh
export PATH="$HOME/.local/bin:$PATH"
```

The installer installs the system packages relay needs, builds relay, puts the `relay` command in `~/.local/bin`, and finishes by running `relay doctor`. It exits with an error if a check fails, and it is safe to run again. Add the `export` line to your shell profile to keep it. If `~/.local/bin` is not on `PATH`, the installer prints `Not on PATH; add it with: export PATH="<prefix>/bin:$PATH"`.

Options: `--prefix DIR` installs somewhere else, `--no-deps` skips package installation, `--no-desktop` skips the XFCE packages, and `--client-only` installs only the CLI (see [step 6](#6-control-it-from-your-laptop)).

## 2. Start a session

```sh
relay up -d
```

`up` starts a virtual display (1280x720 at 60 fps by default), the desktop, and the engine. It waits until the desktop is ready, then prints a viewer link. With `-d` the command returns once the session is ready. Without it, `up` stays in the foreground and the first Ctrl+C stops the session.

Each session has a name, `default` unless you pass `--name`. To run a second session, give it another `--name` and `--port`.

## 3. Open the viewer

The engine listens on `http://127.0.0.1:8080` and is reachable only from the VM. From your laptop, forward the port over SSH:

```sh
ssh -N -L 8080:127.0.0.1:8080 user@your-vm
```

Open the viewer link that `up` printed. On a loopback listener there is no token. If the link has a `#token=` part, treat the whole link as a secret. The viewer removes the token from the address bar before it connects.

<Callout title="Secure context">
  The viewer needs a secure context: `https://` or `http://127.0.0.1`. A blank
  page or a WebCodecs error usually means the browser lacks H.264 WebCodecs or
  the page is not in a secure context.
</Callout>

## 4. Control it from the VM

On the VM, client commands find the session on their own:

```sh
relay screenshot screen.png
relay click 0.5 0.5
relay type "echo hello"
relay key Enter
relay screenshot after.png
```

- Coordinates are fractions from 0 to 1, measured from the top-left.
- `type` sends text using the desktop's keyboard layout.
- `key` presses physical combinations such as `ctrl+l` or `alt+Tab`.
- A successful input command means the engine applied the events. Take another screenshot to confirm the app reacted.
- While a viewer is open, input commands fail with `busy` because the viewer owns input. Screenshots still work. Close the viewer tab to hand control back.

Start an app on the desktop with `relay run`:

```sh
relay run -- xterm
```

`run` prints the app's process ID right away, and the window appears a moment later. Read its output with `relay logs apps`. Apps stop with `relay down`.

Check or stop the session:

```sh
relay status
relay down
```

`status` succeeds for any existing session, including a stopped or failed one. `down` stops the session and everything it started, and it is safe to run twice.

## 5. Make the session reachable

To control a session from another machine, the engine must listen beyond the VM and require a token. The common setup puts HTTPS in front of it:

```sh
relay up -d --public https://desktop.example.com
```

This generates a token and prints a viewer link that includes it. The [Remote access](/docs/remote-access) page covers TLS proxies, native TLS, and tokens.

## 6. Control it from your laptop

On the laptop, install only the CLI. This works on any OS with Node 26 or newer:

```sh
./install.sh --client-only
```

Copy the token from the VM into a file on the laptop:

```sh
relay status --show-token
```

Then point the CLI at the session:

```sh
export RELAY_URL=https://desktop.example.com
export RELAY_TOKEN_FILE=./token
relay status
relay screenshot screen.png
relay click 0.5 0.5
```

You can pass `--url` and `--token-file` on each command instead. Remote plain HTTP is refused, so use HTTPS or an SSH tunnel to `http://127.0.0.1`.

## Use Docker instead

If you would rather not install on the host, run relay in a container. See [Docker](/docs/docker).
