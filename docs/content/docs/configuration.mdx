---
title: Configuration
description: Set relay's display, stream, server, keyboard, backend, and desktop options with a YAML file, flags, or environment variables.
---

Change how `relay up` starts a session with an optional YAML file on the VM. Every key is optional. A flag beats its environment variable, which beats the file, which beats the default.

## Where the file lives

`relay up` uses the first source that matches:

| Order | Source |
| --- | --- |
| 1 | `--config FILE` |
| 2 | `RELAY_CONFIG` |
| 3 | `${XDG_CONFIG_HOME:-~/.config}/relay/config.yaml`, when it exists |

If `--config` or `RELAY_CONFIG` names a file that does not exist, `relay up` fails. Only `relay up` reads the file. The viewer and the client commands do not.

## Default configuration

Copy this file to `~/.config/relay/config.yaml` and change the values you need. The values are the defaults for a new X11 display. `desktop` and `backend` are commented out because their defaults depend on the backend; remove the `#` to set one.

```yaml title="~/.config/relay/config.yaml"
# relay settings. Every key is optional; the values below are the defaults.

display:
  # WIDTHxHEIGHT. Width even 320..1920, height even 240..1080.
  resolution: 1280x720

stream:
  # 10..60.
  fps: 60
  # Bits per second, 250000..100000000. A k or M suffix is 1000-based.
  # Require min <= start <= max.
  bitrate:
    min: 1M
    start: 8M
    max: 40M

server:
  # 1..65535.
  port: 8080
  # bind: 127.0.0.1
  # public: https://desktop.example.com
  # tls_cert: /path/fullchain.pem
  # tls_key: /path/key.pem

keyboard:
  # Layout name such as us, de or fr, or a comma-separated list. Linux only.
  layout: us

# Linux only. xfce, none, or a command. Default: xfce (x11) or foot (wayland), or none with --display.
# desktop: xfce

# x11 or wayland. Default: x11 when the engine has it, else wayland.
# backend: x11
```

To create the file from the terminal:

```bash title="Terminal"
mkdir -p ~/.config/relay
nano ~/.config/relay/config.yaml
```

## Keys

| Key | Default | Allowed values | Flag | Environment variable |
| --- | --- | --- | --- | --- |
| `display.resolution` | `1280x720` | The desktop size as `WIDTHxHEIGHT`, both even. Width 320 to 1920, height 240 to 1080. Ignored with `--display`, which uses the existing screen's size. | None | `RELAY_RESOLUTION` |
| `stream.fps` | `60` | Whole number from 10 to 60 | None | `RELAY_FPS` |
| `stream.bitrate.min` | `1M` | 250000 to 100000000, as a whole number or with a `k` (thousand) or `M` (million) suffix. No higher than `start`. | None | `RELAY_BITRATE_MIN` |
| `stream.bitrate.start` | `8M` | Same values as `min`. The stream adjusts between `min` and `max` from here. | None | `RELAY_BITRATE_START` |
| `stream.bitrate.max` | `40M` | Same values as `min`. No lower than `start`. | None | `RELAY_BITRATE_MAX` |
| `server.port` | `8080` | 1 to 65535 | `--port` | `RELAY_PORT` |
| `server.bind` | `127.0.0.1`, or `0.0.0.0` when `server.public` is set | An address on the VM. Any other address makes relay generate a token. | `--bind` | `RELAY_BIND` |
| `server.public` | unset | HTTPS origin with no path, query, or credentials, such as `https://desktop.example.com`. The engine accepts requests only for this host, from any origin that sends the token. | `--public` | `RELAY_PUBLIC` |
| `server.tls_cert` | unset | Path to a certificate file. Set with `tls_key`. | `--tls-cert` | `RELAY_TLS_CERT` |
| `server.tls_key` | unset | Path to the private key file. Set with `tls_cert`. | `--tls-key` | `RELAY_TLS_KEY` |
| `keyboard.layout` | `us` | A layout name such as `de` or `fr`, or a comma-separated list such as `us,de`, using letters, digits, `_`, and `-`. On X11 it needs `setxkbmap`, which `relay doctor` checks. | None | `RELAY_KEYBOARD_LAYOUT` |
| `backend` | `x11` when the engine includes it, else `wayland` | `x11` or `wayland`. See [X11](/docs/x11) and [Wayland](/docs/wayland). | `--backend` | `RELAY_BACKEND` |
| `desktop` | `xfce` on X11, `foot` on Wayland, or `none` with `--display` | `xfce`, `none`, or a command. See [X11](/docs/x11) and [Wayland](/docs/wayland). | `--desktop` | `RELAY_DESKTOP` |

`stream.bitrate` needs `min <= start <= max`, including when you change one value. `server.tls_cert` and `server.tls_key` must be set together.

To reach the session from outside the VM, set `server.public` or serve it through a TLS proxy. In a container, publish the port to the host loopback. See [Remote access](/docs/remote-access) and [Docker](/docs/docker).

## Bad values

`relay up` refuses to start and names the file and key when a value is wrong. It does not fall back to a default. Unknown keys, wrong types, and values outside the allowed range are all errors, and a bad value from a flag or environment variable fails the same way.

## Apply changes

Settings apply when `relay up` starts. There is no live reload and no live resize. To change a setting, stop the session with `relay down`, edit the file, and run `relay up` again.
