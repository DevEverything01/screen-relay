title: Wayland
description: Start a headless Wayland desktop or attach to an existing compositor.
---

Wayland is the newer Linux display server. screen-relay starts a headless sway desktop, or attaches to a wlroots-based compositor you already run. screen-relay calls this the backend: choose it with `--backend wayland`.

## Install

Install the CLI as described in [Getting started](/docs/getting-started#install-screen-relay), then set up Wayland:

```sh
npm install -g screen-relay
screen-relay install --backend wayland
```

Setup installs sway, XWayland, and foot, then builds the engine. To set up both backends, run `screen-relay install --backend all`. Adding a backend keeps the ones the engine already has.

## Start a desktop

```sh
screen-relay up -d --backend wayland
```

screen-relay starts headless sway with XWayland and a foot terminal by default. It needs no GPU. Use `--desktop none` to skip the terminal, or `--desktop COMMAND` to start another command. The output uses `display.resolution` from your [configuration](/docs/configuration), or `1280x720` by default.

To open the viewer, follow [Getting started](/docs/getting-started#open-the-viewer).

## Attach to an existing display

From a terminal in your compositor session, run:

```sh
screen-relay up -d --backend wayland --display "$WAYLAND_DISPLAY"
```

screen-relay captures the first output at its existing size and starts no desktop by default. To choose an output, add `--output OUTPUT`, replacing `OUTPUT` with its name. On sway, list outputs with `swaymsg -t get_outputs`; on Hyprland, use `hyprctl monitors`.

screen-relay needs the compositor's `XDG_RUNTIME_DIR`. If it is unset and the compositor uses `/run/user/$(id -u)`, run `export XDG_RUNTIME_DIR=/run/user/$(id -u)` before starting screen-relay. Stopping screen-relay leaves the compositor running.

If the output is outside the [size limits](#limits), create a headless output with `swaymsg create_output` or `hyprctl output create headless screen-relay`, configure it to a supported size, and select it with `--output`. Move a window or workspace onto that output to see it in the viewer.

## Check the machine

```sh
SCREEN_RELAY_BACKEND=wayland screen-relay doctor
```

The checks cover:

- The engine, required libraries, and default port.
- `sway`, `swaymsg`, `Xwayland`, and `foot`.

Doctor does not check the protocols of an existing compositor. If sway fails to start, run `screen-relay logs display`.

## Limits

<a id="compositors"></a>

| Compositor | Status |
| --- | --- |
| sway, labwc | Tested |
| Hyprland (including Omarchy), river, wayfire, niri | Untested |
| GNOME, KDE | Not supported |

- The compositor must provide `wlr-screencopy` version 3, `wl_shm` with XRGB8888 or ARGB8888 frames, the virtual keyboard protocol, and virtual pointer version 2.
- The output must be 320 to 16384 pixels wide and 240 to 16384 pixels high, with even dimensions. Its size is fixed for the session; restart screen-relay after changing it.
- Selecting an output by name requires `wl_output` version 4.
- The cursor image is not streamed. The viewer shows its own arrow.
