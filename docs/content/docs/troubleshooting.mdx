---
title: Troubleshooting
description: Find and fix common relay problems.
---

Find session problems on the VM:

```sh
relay doctor
relay logs
```

Follow the fixes from `doctor`. For a named session, add `--name NAME` to `relay logs`. Run `relay logs engine --follow` to follow a component. See the [CLI reference](/docs/cli#error-reasons) for error reasons.

Stopping a session also stops the processes it started. Save your work before running `relay down`.

## Install and setup

| Symptom | Cause and fix |
| --- | --- |
| `relay: command not found` | Run `export PATH="$HOME/.local/bin:$PATH"` and add it to your shell profile, or run `~/.local/bin/relay`. |
| The installer rejects the distribution or needs privileges | Automatic dependency installation needs a [supported distribution](/docs/getting-started) and root or passwordless `sudo`. Otherwise, install dependencies yourself and run `./install.sh --no-deps`, or `./install.sh --client-only --no-deps` for the client alone. |
| The Fedora installer asks for RPM Fusion | Run the printed command, then rerun `./install.sh`. |
| `unsupported_platform` | Run `up`, `down`, and `run` on the Linux or macOS machine. On your laptop, install with `./install.sh --client-only` and use the [client commands](/docs/remote-access). |
| `missing_dependency` or a failed doctor check | Run the suggested fix. See [X11](/docs/x11), [Wayland](/docs/wayland), or [macOS](/docs/macos) for backend checks. |
| XFCE exits with a `default_icon_at_size` assertion on Ubuntu 26.04 | Install the icon loader with `sudo apt-get install glycin-loaders`, or rerun `./install.sh`. |

## Starting a session

| Symptom | Cause and fix |
| --- | --- |
| `already_running` | Stop the existing session with `relay down --name NAME`, replacing `NAME` with its name, or start another with a different `--name` and `--port`. |
| `Cannot listen on 127.0.0.1:8080` in the engine log | The port is in use. Choose a free port, for example `relay up --port 8081`, or stop the session using it. |
| `component_failed` or `status` shows `failed` | Run `relay logs`, or `relay logs COMPONENT` for the component named in the error. For a background session, also check `supervisor.log` in the [state directory](/docs/cli#state-directory). |
| `timeout` while the engine or desktop starts | The default readiness timeout is 30 seconds. Check the error's log tail, then try `relay up --timeout 90` on a slow VM. This does not extend the display startup timeout. |
| `invalid_config` | Correct the file and key named in the error. See [Configuration](/docs/configuration). |
| `opening X display failed` with `--display` | Check the display number and `XAUTHORITY`; see [X11](/docs/x11#attach-to-an-existing-display). |

## Viewer and streaming

| Symptom | Cause and fix |
| --- | --- |
| WebCodecs unavailable or a decoder error | Check the viewer status. Use a browser with H.264 WebCodecs and open the viewer over `https://` or `http://127.0.0.1`. |
| The viewer cannot connect through a proxy | Forward WebSocket upgrades, preserve `Host` and `Origin`, and use the `--public` URL. See [Remote access](/docs/remote-access). |
| The picture is too small or blurry | Under **Scaling**, choose **Actual size** or **Sharp pixels**. To resize the desktop, set `display.resolution` and restart. With `--display`, relay uses the existing screen size. See [Configuration](/docs/configuration). |
| The desktop streams at about 60 fps although `stream.fps` is higher | XFCE compositing caps repaints at the display refresh rate. Turn it off as described in [The desktop holds at 60 fps](#the-desktop-holds-at-60-fps). |
| The picture is blocky although the desktop fills the viewer | The stream may sit at its minimum bitrate. Read `target_bitrate_bps` from `relay status --json`, then raise `stream.bitrate.min` if the link can carry more. See [Configuration](/docs/configuration). |
| `resources_available: false` | Relay cannot read valid cgroup v2 counters. Ensure `/sys/fs/cgroup/cpu.stat`, `/sys/fs/cgroup/memory.current`, and `/sys/fs/cgroup/memory.stat` are readable. Streaming is unaffected. |

### The desktop holds at 60 fps

A compositing window manager repaints at the display refresh rate, so the engine captures at most one frame per refresh however high `stream.fps` is set. The XFCE desktop that `relay up` starts enables compositing.

Turn compositing off for the session display. Read `display` and `xauthority` from `relay status --name NAME --json`, then run:

```sh
export DISPLAY=:0 XAUTHORITY=/path/from/relay-status/Xauthority
xfconf-query -c xfwm4 -p /general/use_compositing -n -t bool -s false
xfwm4 --replace
```

The setting is stored in `~/.config/xfce4` and applies to later sessions in the same home directory. If a restarted session brings compositing back, a saved XFCE session is restoring it. Move the profile aside, then start the session again with the flags you used before:

```sh
mv ~/.config/xfce4 ~/.config/xfce4.bak
relay up -d --public https://your-host
```

Compare the result in the viewer's **Stream statistics**, which reports the frames actually drawn. With compositing off, a 1280x720 session set to 120 fps draws at the configured rate while the encoder uses a fraction of one core.

## Input

| Symptom | Cause and fix |
| --- | --- |
| `busy` from input (HTTP 409) | Another viewer or controller owns input, or the input queue is full. Close the other owner or wait for input to finish, then retry. If present, `data.applied` counts events already applied. Screenshots remain available. |
| `busy` from `screenshot` (HTTP 503) | Another screenshot is running. Retry after it finishes. |
| Text has the wrong case | Local and desktop Caps Lock states can differ. Reload the viewer and press Caps Lock to set the desired state. Local Caps Lock does not affect `relay type`. |
| Characters are wrong or `unsupported_input` | Set `keyboard.layout` and restart. With `--display`, change the existing desktop's layout instead. Use `relay type` for text and `relay key` for shortcuts. See [Configuration](/docs/configuration). |
| Mac Command shortcuts behave differently | Open **Send keys** and turn off **Use ⌘ as Ctrl** to send Command as Super instead of Ctrl. |

## Remote access

| Symptom | Cause and fix |
| --- | --- |
| `unauthorized` (HTTP 401) | The token is missing or wrong. Run `relay status --show-token` on the VM and update the file used by `--token-file` or `RELAY_TOKEN_FILE`. For the viewer, open the link printed by `relay up`. Restarting a session generates a new token when required. |
| `forbidden` (HTTP 403) | The `Host` or `Origin` is not allowed. Connect through `127.0.0.1`, `localhost`, or the `--public` URL. Configure the proxy to preserve both headers. |
| `invalid_input` about a URL or plain HTTP | Use an HTTPS origin without a path, query, or credentials, and pass a token for remote hosts. Plain HTTP works only for `localhost` and `127.0.0.1`; use an [SSH tunnel](/docs/remote-access) if needed. |
| `unreachable` | Check the URL and run `relay status` on the VM. If the certificate was rejected, use one the client trusts. |

## macOS

| Symptom | Cause and fix |
| --- | --- |
| `Screen capture permission is missing` or `Accessibility permission is missing` | In **System Settings > Privacy & Security**, enable **Screen & System Audio Recording** and **Accessibility** for the app that starts relay, such as your terminal. Then restart that app and run `relay doctor`. See [macOS](/docs/macos#grant-permissions). |
| `Display N not found; active displays:` | Pick an ID from the list in the error and pass it with `--output`. See [macOS](/docs/macos#choose-a-display). |
| `The display changed ... restart relay to stream it` | The display's size or position changed. Run `relay up` again. |

## Wayland

### Engine exits with a missing Wayland protocol

The compositor lacks a required protocol, causing `component_failed` for the engine. Attach to a supported compositor listed in [Wayland](/docs/wayland).

| Symptom | Cause and fix |
| --- | --- |
| `Unsupported root size` when attaching | Create a supported headless output and pass its name with `--output`; see [Wayland](/docs/wayland#attach-to-an-existing-display). |
| `missing_input`: `XDG_RUNTIME_DIR is required` with `--display` | Set the compositor's runtime directory; see [Wayland](/docs/wayland#attach-to-an-existing-display). |
| `component_failed` for `display` or `timeout` while sway starts | Sway exited or did not report its Wayland and XWayland displays within 15 seconds. Run `RELAY_BACKEND=wayland relay doctor`, then `relay logs display`. |
